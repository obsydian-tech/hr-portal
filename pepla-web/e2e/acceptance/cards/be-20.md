Lock: acceptance-lock/be-20

Nothing here opens the app. All six tests run once, in `desktop-1280`. BE-18 already ships all of this, so
the tests pass on develop: they guard BE-18's rules from here on.

- **AC-1** who gets in: only the employee group on the start page and consent, no owner with an empty
  address, two rows with one address are no record, only the actor `AGENT` is the Agent API, and
  `email_verified` counts only as `true` or `"true"` (anything else is the not-found answer).
- **AC-2** logs and printed output: no address when an invite is refused, no invite token or error text when
  the invite lookup fails, the address script prints the error name only, and the idempotency wrapper logs
  the error name, never the error text, on the decide-a-document route and in both copies. A repeat with
  the same key still gets the cached answer, and a request already in progress gets 409 without the route
  running, in both copies.
- **AC-3** reads `infra/*.tf` as text: no `kms:` action reaches the consent or start-page role through a
  policy document, directly or through an attached `aws_iam_policy`, and every such document lists its
  actions literally (an action list from a local or variable fails).
- **AC-4** the email check answers `{ inUse }` or `{ error }` only, and finds a row by the address as typed
  or its lower-case form.
- **AC-5** the post sign-in stage bump keeps a stage someone else set, and the address script stops on a
  real write failure.
- **AC-6** HR asking the own list for a missing employee gets `Employee not found`.

Words: no new words. Every answer is the route's existing text.
