## How the tests run

Every test runs at 1280 and 390 wide unless it says why not. The page clock is fixed at 19 Nov 2026 10:00 in Johannesburg (the harness).

The fake (`offers-fake.ts`) answers `/v1/offers` and the offer routes the way `offers.mjs` does: the same answer shape, `version` required on approve, send back and PATCH (409 STALE when it does not match), the same codes, 403 for the drafter on approve or send back, and one answer per idempotency key. Every request and answer is checked against `api/openapi.yaml`; a contract problem fails the test. `refuse()` makes the next matching call fail with a given status and code, hold, or abort.

`kit.ts` is generated by `onboarding-cards/rec-ui-04/gen-kit.py` from `project/ui_kits/recruitment.html` at design system ref 5eed22c (PR 67, which drew the K-1 screens). The app stays synced at 449bc5b: between the two refs only `project/ui_kits/recruitment.html` and `recruitment.md` changed, which the generator checks, so no ref bump and no child lock on another card is needed. AC-13 first checks the app is still synced to 449bc5b.

AC-14 runs on pepla-dev only (`ACCEPTANCE_TARGET=pepla-dev`, `@pepla-dev`). It needs `E2E_HR_EMAIL` and `E2E_HR_PASSWORD` (HR with the Recruitment tick in company A) and an Employee login. It sends nothing to a candidate.

## Things the builder must know

1. Offers needs Recruitment switched on and either the Hire access (hr_staff and the Recruitment tick) or the Approve offers tick. The nav entry and the route guard ask the same question (`allowed()` in `core/nav.ts`). Put `module: 'recruitment'` on the top level of the access rule: the guard loads the company's modules only when the rule names a module at the top.
2. Draft a new offer (`/hire/offers/new?candidate=…`) is Hire access only. Roles, Pipeline and Candidates stay Hire access only.
3. A first save is one POST with an idempotency key and only the allowed fields (no role, title or company). Later saves are one PATCH with only the changed fields and the `version`. Submit with an unsaved change saves first. A double press sends one request.
4. The salary is never in the list, an address, storage, a console line or any request other than the one reveal read (`GET …?reveal=salary`), made only when the person presses Show. Reload hides it.
5. Design system radio tiles: the label covers the input, so the tests pick a tile with a forced check; use `pp-radio-group` (tiles) in the Record answer drawer.
6. The page never says the candidate is emailed or told, and makes no call beyond `/v1/offers` and what the shell already makes.
