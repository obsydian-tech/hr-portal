# SITE-10

Card: SITE-10 Learn more page: Onboarding and Offboarding (NH-215, epic NH-202)

Test files: `site-10.spec.ts`, `support/site-10/page.ts` (the Onboarding page's own checks), `support/site-10/build.ts` (the production build and a static server for it), `support/site-10/files.ts` (the AC-13 file rule).

Spec: [NH-215](https://obsydian.atlassian.net/browse/NH-215)

Locks: acceptance-lock/site-10

It imports, and never edits, `support/site-08/learn-page.ts` and `support/site-08/kit.ts` (SITE-08, NH-213: the page helper, with the child lock site-08.1 that waits for fonts, and the kit oracle) and `support/site-01/public-site.ts` (the Cognito and API patterns of SITE-01). It needs SITE-08 merged: without `support/site-08/` the spec does not load. Before every region compare against the kit (demo steps included), `compareRegion` makes both pages wait for `document.fonts.ready`, sends a `resize` event and sleeps 150ms (`fontsAndResize`, its own copy), so the kit's measuring scripts run again on the loaded font; the SITE-08 helper does the same for its own checks. It shares no file with SITE-09 (the same method, its own copies).

## How the tests run

```
E2E_BASE_URL=http://localhost:4200 npx playwright test -c e2e/acceptance/playwright.config.ts site-10
```

Every test runs at 1280 and 390 wide, except AC-3 (1440 and 390: the kit's desktop screen is 1440) and AC-13 (reads the repository and the build once, in `desktop-1280`). The browser starts with `--disable-lcd-text --font-render-hinting=none`. The build (`npm run build`, which runs `verify:design` first and `verify-public-names` last) runs once per test run, in AC-1, and AC-2 and AC-13 read the same output. `SITE_10_BUILD_DIR` points the tests at an existing build output instead (for trying a changed output by hand; CI does not set it).

## Contract (what the builder makes)

1. Route `/product/onboarding`, lazy, in `site.routes.ts` (`canActivate: [siteStyles]`, title "Naleko People"), and `{ path: 'product/onboarding', renderMode: RenderMode.Prerender }` in `app.routes.server.ts`. The page lives in `src/app/ds/site/learn/onboarding/` (at least one `.ts` file that is not a spec).
2. The page is one `h1`, one `main`, the header and the footer. A `.pp-site-form-page--learn` hero (the Learn more page top) is a child of the one element that also holds the sub-menu, the demos, the ending and the closing band (the SITE-08 helper takes its root from it: `.pp-site-form-page--learn`'s parent). The footer may sit in that element or outside it (it is judged by its own check).
3. Section ids exactly: `employee`, `documents`, `follow-ups`, `contract`, `laptop`, `offboarding`, `questions` and the closing band `demo`, each once, each element named by a heading inside it through `aria-labelledby`. Sub-menu tabs in that order, named "New employee’s side", "Documents read and matched", "Follow-ups", "Contract and probation", "Laptop and access", "Offboarding", "Questions" (the tab has the typographic apostrophe, the demo's small label above its heading has the straight one, as in the kit), with `#` targets.
4. The hero card is `.pp-site-hcard[data-demo="hcard-onboarding"]`. The demos are `section.pp-site-demo` with the kit's classes (`pp-site-phone__*`, `pp-site-read__*`, `pp-site-timeline__*`, `pp-site-contract__*`, `pp-site-checklist__*`, `pp-site-state__item--on`, `pp-site-step--in`, `pp-site-demo__again`), `data-site-live` once started. Five of the six have a `button.pp-site-demo__again`; **the sample phone (`#employee`) has none in the kit**: it loops on its own (it restarts 16.5s after it began). The spec's AC-6 says "Play again replays it"; the kit has no such button, so the tests follow the kit (the same rule as SITE-08: tests follow the kit and the difference is logged). A builder who adds the button changes the words and the page parity (AC-2, AC-3) fails.
5. A demo starts when 15% to 60% of it is in view (the kit starts at 35%; the spec says 15%; the tests judge "not at 12%, started at 60%"). Once started it plays once (the phone loops), keeps its place and replays from its first step with Play again, which keeps focus.
6. `data-site-still` on the `html` element: every demo and the hero card show their last step at once, nothing loops (the phone's restart and the hero card's restart included). Under `prefers-reduced-motion: reduce` every demo, the hero card and Ask Batsi keep the kit's timings (fades, colour changes, counts, ticks, slow light and drift, loops at the kit's slower durations); no script slides anything (`element.animate` of a transform: a flying card, a sliding step); grain and pointer tilt do not exist on this page in the kit.
7. Links with `href="#"` do not matter to these tests (the spec leaves link targets to SITE-16).

## What each test judges

The production build holds `product/onboarding/index.html` (or `.html`) with the tab title, a `header`, exactly one `main`, and every `h1` and `h2` of the kit page in its text; served as static files (a small server with no fallback to the app shell, 404 for an unknown path) with JavaScript off, the header, one `main`, one `h1` and every heading of the kit screen are visible.
- AC-2 the page's words and accessible names equal the kit screen's, both ways: the SITE-08 helper's `checkPageWords` on the page's own box, and the same set check on the whole page and the whole kit screen (header, page, footer; the phone sheet is left out on both sides). No `lorem`, `placeholder`, `masked`, `claude` or `pepla` in the rendered page's text, attributes, classes, `href`s or title, nor in the prerendered file.
- AC-3 at 1440 and 390 with motion frozen and the views frozen: the helper's `checkPageParity` (every kit item in order, each box within 1px), then at most 1% of pixels differ over the whole page and over the footer (own pixel check: a real page is not in a `.pp-site-stage`, which the SITE-08 pixel path needs; the page is taken in 2400px slices, pixels count as in SITE-08: a channel difference over 24 against the other page's pixel and its neighbours above and below), and the same 1% on each part of the page apart: the page top, the sub-menu, Ask Batsi, the trust strip, Works together with, the questions and the closing band (a tinted lead box is 0.5% of a whole page and passed SITE-09's whole-page rule; a part of its own takes it over 1%). ## Where the card and the tests differ

- AC-6 "Play again replays it": the kit's sample phone has no Play again and loops on its own (see the contract); the tests follow the kit. To be confirmed with the BA: either the spec line goes, or a design system change adds the button (then the kit is re-pinned).
- AC-5 runs SITE-08's `checkSubmenu` with `deaf: true` (demos stay on their first step) on a page opened under `prefers-reduced-motion: reduce`, so the kit's own rule makes the sub-menu's scroll instant. The helper's tap check scrolls past all six demos; with smooth scrolling on a busy machine the scroll starts late, the kit's 180ms settle re-aims it mid-animation and the page ends 20 to 800px away from where it should (the kit's own script, reproduced 4 runs in 5 at load 5 with `deaf` alone; 5 of 5 green with the reduced motion open step). The landing position (112px, 4px) is judged as before; smooth scrolling of the shared sub-menu is SITE-08 AC-4's.
- AC-12 runs `checkMotion` on a page whose open step switches off the transition of the phone header's menu button (`.pp-site-header__burger`, the shared header). SITE-08's colour allowance names `pp-button` as the first class and the burger's first class is its own, so the helper counts the burger's `background-color` transition as a problem. Open question for the SITE-08 owner: widen the allowance (the same note as SITE-09).
- Each picture of a region counts only when the region sat still before and after it (a demo elsewhere can change height while the pictures are taken).
- Pixel checks photograph both pages scrolled to the top, so the sticky header and sub-menu sit over the hero and not over the region compared.
- Start threshold: the card says 15%, the kit starts at 35%. The tests judge "not started at 6%, started at 60%", so any threshold from 15% to 60% passes (as SITE-08).
- AC-3 desktop is read in a 1440 window (the kit's desktop screen); the other desktop checks use the project's 1280 window, where the kit page's stage takes the window's width too.
- The footer sits outside the helper's page box on a build that uses `PpSitePage` (the footer is projected after `main`), and inside the kit's. So the helper's whole-page checks leave it out on both sides (`omit`), and the footer has its own words, box and pixel checks.
- The hero card's last step under `data-site-still` is read from the kit's own run (its state between the last step at 8.7s and the restart at 11.9s), since the kit's script shows the first step, not the last, under `data-site-still`.
- Under `data-site-still` the kit's demo scripts do nothing (they ignore the attribute); the end state is the end of the kit's own run on a live page, and the app is judged against it.
- The kit's static markup (before any demo starts) shows each demo's last step and the hero card's first; AC-3 compares the page in that state, as the kit draws it (the spec's "first step" there means the kit's resting state).
- AC-11 "tilt", grain and a flying card: the kit's Onboarding page has none, so there is nothing to judge; reduced motion is judged on what the kit has (timings, no script slides).
- Link targets ("Book a demo", "Get started", "Learn more") are not judged (SITE-16).
