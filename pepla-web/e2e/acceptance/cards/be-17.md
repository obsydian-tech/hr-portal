# BE-17

Card: BE-17 Only HR reaches HR routes, now that employees can sign in (NH-190)

Test files: `be-17.spec.ts`, `support/be-17/`, and the file link row of AC-5 in `onb-15.spec.ts` (moved, see below)

Spec: [NH-190](https://obsydian.atlassian.net/browse/NH-190)

Locks: acceptance-lock/be-17, acceptance-lock/onb-15.2 (same commit)

Nothing here opens the app. AC-1 to AC-5 run the real handlers of the ten routes, each call in its own
fresh Node process (a cold Lambda), against a fake AWS (`support/be-17/fake-aws`, copied from ONB-15's
with code added only): DynamoDB takes writes, honours `ConditionExpression`, and answers the
`employeeId-index`, `email-index` and `created_by-index` queries; KMS, the S3 URL signer, EventBridge
and CloudWatch record what they are asked. Bedrock, Secrets Manager, Cognito and outbound HTTP (`fetch`)
are recorded and refused, so a model call, a secret read or an Agent API call shows up as a call and
fails. `world.fail` makes chosen DynamoDB calls throw, for AC-5's "no exception words in a 500".
These run once (in `desktop-1280`).

Callers: HR (`[hr_staff]`, a robot email, so the AI routes take the AI-skipped path), Employee
(`[employee]`, record A's email), Look-alike (`[not_hr_staff employee]`), No claims, and Agent
(`authorizer.lambda.actor` AGENT). A Lambda actor other than AGENT is refused like anyone else. AC-3 runs the Agent's summary and one risk check with
`AI_CALLS_ENABLED=false`, because the Agent API has no person behind it and the test must never reach a
model.

AC-5 also reads the handlers as text (comments stripped): from the handler's start, `hrOnly`,
`hrOrAgent` or `requireHr` comes before the first `.send(`, `markRobot(`, `isRobotCaller(`, `guardAi(`,
`withIdempotency(`, `getSignedUrl(` and the old lookup helpers. The two owner routes (upload link, file
link) read one row first, so there `isHrOrOwner` must come before `getSignedUrl(` and `PutItemCommand(`.

AC-6 reads `api/openapi.yaml` and `lambda/serveDocs/spec.yaml` with ONB-15's `openapi_route.py`, and
Terraform as text: every resource in `support/be-17/infra.629ae93.tf.txt` (this card's routes,
their authorizers, the roles and policies of its Lambdas, the `kms_pii` module, all as on develop at
629ae93) must still be there once and unchanged, except two allowed changes: the file link's policy may
gain `dynamodb:GetItem` on `employees` (and nothing else), and `kms_pii` `dynamodb_read_role_arns` may
gain the upload-link and file-link roles. `kms_pii` is judged only for this card's nine roles, so another
card that adds its own reader of `employees` does not break this test.

AC-7 runs on pepla-dev only (desktop, once). It reads the dev API addresses from the CI-written
`environment.ts` files (the hr-portal one only when it carries the "Generated in CI" line, because the
committed file holds a prod address). It asks HR only for read routes (`GET /v1/employees` to find the
seeded Naledi Dlamini, then `GET /v1/employees/by-email`), and asks the employee login for the read
routes first, so on a pepla-dev that still runs the old Lambdas it fails before any call that could
write. Between the two sign-ins it calls ONB-23.1's `forgetSignIn` (`support/sign-in-again.ts`), because
HR's session is kept and `/sign-in` would otherwise send the browser on without asking for the employee.
The commit sits on ONB-23.1's test commit 7b61f82, so `onb-15.spec.ts` carries both changes.
